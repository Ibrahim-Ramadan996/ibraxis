# 25. AUTONOMOUS EXECUTION RULES

## Repository Inspection

Before changing anything:

1. Inspect the repository.
2. Read existing documentation.
3. Inspect package files.
4. Inspect source code.
5. Inspect Git status.
6. Identify existing implementations.
7. Identify incomplete or broken components.

Never assume the repository is empty.

Never overwrite working code without understanding it.

## Feature Implementation

For every feature:

1. Understand requirements.
2. Identify dependencies.
3. Design the implementation.
4. Implement it.
5. Validate inputs.
6. Handle errors.
7. Write tests.
8. Run tests.
9. Fix failures.
10. Update documentation.

## Quality Gates

A feature is not complete just because files were generated.

Before marking it complete:

- Build must succeed.
- Relevant tests must pass.
- Type checking must pass.
- Linting must pass.
- Security boundaries must be reviewed.
- Documentation must be updated.
- Known limitations must be documented.

If testing is blocked by missing external accounts or credentials, mark the feature BLOCKED or NOT VERIFIED.

## Git Safety

Never:

- Delete unrelated user files.
- Force-push without explicit approval.
- Reset or overwrite user work.
- Commit secrets.
- Deploy to production without approval.
- Run destructive database migrations without approval.

Use branches and meaningful commits.

## Autonomous Decisions

Make routine implementation decisions independently within the approved architecture.

Document significant decisions in ADR files.

Ask the owner before:

- Paid Subscriptions.
- Paid API Usage.
- Production Deployments.
- Destructive Changes.
- Permanent Data Deletion.
- Security Changes.
- Permission Changes.
- Public Publishing.
- Sensitive Data Transfers.
- External Commercial Commitments.

Do not repeatedly interrupt the owner for minor implementation decisions.

Choose sensible defaults, document them, and continue.
