# Security model
Owner provisioned manually; disable open admin signup. Verify Supabase JWT server-side (signature, issuer, audience, expiry), resolve roles server-side, and use user-scoped DB access with RLS. Never expose service-role keys to browsers. Public submissions through validated bounded API with spam/rate controls; private inquiries have no public read policy. Reject cross-owner access, test IDOR. Exact origin CORS, CSP and security headers; CSRF checks where cookie auth is used. Validate all inputs and output projections. Private uploads: size/type checks, quarantine, no execution, signed short-lived URLs. Prevent SSRF for imports; protect against archive traversal and zip bombs. Encrypt OAuth tokens with separate server secret; redact sensitive logs. AI tools allowlisted, no raw DB or shell access. Approvals bind actor, action, exact payload and expiry; invalidate on edits. Audit sensitive operations. Threats: token theft, RLS bypass, injection, malicious uploads, prompt injection, accidental disclosure and duplicate jobs. Test each boundary before production.

V0.8: design uses fixed CSS variable names, validated hex colors, enum options and escaped/textContent names; no arbitrary CSS or HTML injection. Owner-only settings mutation/history/reset/restore. Public section hiding is not access control. Custom palette contrast is owner responsibility.

V0.9: Server-rendered HTML and sitemap rely on published-only queries and linked showcase visibility. All dynamic HTML escaped, JSON-LD escapes script delimiters, canonical origin configured rather than inferred from request Host. Private staging and admin noindex. Noindex is not authentication. Public HTML is no-store; public CSS/JS cache for one hour with ETags. Hiding a linked report in IBRAXIS does not revoke third-party access.

## V1.0 storage controls
Private GitHub repository only, separate token and repository restricted to Contents read/write, no auth hashes in remote checkpoints, no credential values in code, Git SHA/manifest checksum verification and non-force commits. Git history can retain private data; repository access must remain strictly limited. One writer, no manual modifications to managed db directory. All locally stored user/client content requires appropriate transfer consent before enabling GitHub. Import cap remains 5 MiB and path checks exclude unsafe/conflicting paths. Published file downloads explicitly opt-in; no public access if hidden. No real third-party or production verification yet.
